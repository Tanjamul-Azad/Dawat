## Advisor interpretation

Current security groups: deny-all RLS private tables **7 INFO**; intentionally callable anonymous SECURITY DEFINER RPCs **5 WARN**; authenticated scoped RPCs **19 WARN**; leaked-password protection disabled **1 WARN**. These are not a zero-warning security sign-off. App authentication uses OTP, so the password warning is not evidence of a current password-login bypass; review if passwords are enabled later. Scoped RPCs require continued negative authorization tests, not blanket grants or blanket revocation that breaks guests.

References: [deny-all RLS](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy), [anonymous RPCs](https://supabase.com/docs/guides/database/database-linter?lint=0028_anon_security_definer_function_executable), [authenticated RPCs](https://supabase.com/docs/guides/database/database-linter?lint=0029_authenticated_security_definer_function_executable), [password protection](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection), [FK indexes](https://supabase.com/docs/guides/database/database-linter?lint=0001_unindexed_foreign_keys), [RLS init plans](https://supabase.com/docs/guides/database/database-linter?lint=0003_auth_rls_initplan).

The current Supabase changelog was checked. Its upcoming November 10 TLS cipher change concerns old clients; no relevant schema/Auth/Storage change was needed for this audit.

## Delivery order and stop conditions

1. **Client usability and correctness:** A01/A02, A11/A12, core A13/A14. One/two-event setup, meaningful Bangla fields, draft/live sharing accuracy, clear publish-first path, wrong-account/recovery states. Preserve Jamdani renderer/art and current transactional model.
2. **Hosted rehearsal:** A03/A05/A06. Isolated fictional order/customer X + Y; OTP/MFA, editor/photos, failed save/publish, named scope, RSVP/wish, export, pause/expiry/revoke and two-device confirmation. Keep the actual pilot untouched unless the user elects to use it for this rehearsal.
3. **External controlled pilot:** A04/A07/A08/A09/A10/A16. HTTPS frontend, canonical origins, real recipient identity, recovery and operation evidence, phone/accessibility/performance checks. Localhost is not the client-delivery URL. Production/staging separation must be deliberate.
4. **Public website:** browse one real template → demo → package/contact/manual order/status. Automated payment remains separate: gateway callbacks, amount/currency/replay/refund/reconciliation and activation controls before live checkout. Claims/outbox automation is optional for a manually provisioned pilot, not a prerequisite to every client test.

No blanket “all corner cases pass” claim. The [96-case audit matrix](../qa/client-v1-audit-matrix-2026-10-21.md) records automated evidence, confirmed gaps, pending qualification and explicitly deferred features separately. Close findings with evidence and rerun only affected checks; do not turn historical screenshots or registry audits into production certification.
