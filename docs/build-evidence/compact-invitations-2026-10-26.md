# Compact invitations — 26 October 2026

The guest manager now treats an invitation as a named person, couple, family or group, without forcing a family classification or changing stored customer records. The summary table keeps only name, selected-event response, confirmed/allowed people, link state and copy action. Clicking the name/chevron opens one full-width detail panel at a time; private notes, personal text, preview, correction/history and link replacement/revocation remain available there. Duplicate names retain distinct IDs and show an available private note as a distinguishing hint.

Large-list behavior remains server-paginated at 25 entries. Added a successful-page cursor trail for previous/next/first navigation. Search submission resets pagination; paging, background refresh and CSV export use applied filters, rather than half-typed search text. Failed requests retain the previous page and data. Existing link revocation, event scopes and per-event totals are preserved.

The add/edit form explains individual/group use and independent replies, defaults allowance to one, accepts Bangla numerals, disables allowance fields for unchecked events and protects events with saved replies. Optional personal greeting/message fields are collapsed. Labels and handoff wording cover individuals as well as groups in both product languages.

Validation: synthetic Postgres regression with **1,000 invitations over 40 pages**, no duplicate/missing IDs, 25-entry bounds and exact-name search; single-person RSVP accepts one and rejects an extra person. Component regressions cover disclosure, duplicate names, revoked/missing links, pending vs declined, applied-filter pagination/export, failed requests, Bangla-numeral entry and retaining checked protected events when disabled form controls are omitted by FormData. Optimized build/typecheck passed. Final suite: **281 tests / 33 files**. Local browser verification measured approximately 59px desktop / 95px mobile summary rows, keyboard expansion, actual 25/5-entry next/previous pages, and no horizontal overflow at 320px. No production test invitations or schema/grant changes. Live read-only verification and screenshots are retained in ignored `.artifacts/client-handoff/`.

Limits: the 1,000-entry test verifies result correctness/bounds; it is not a hosted concurrent-load benchmark. Cursor pages are live views, not immutable snapshots. No bulk importing, guessed invitation classification or alphabetical global sorting is claimed.
